# Decisions Log

This log records every design decision and judgement call I made during implementation, with a brief rationale for each. It feeds the decisions section of my final evaluation report.

| # | Decision | Rationale |
|---|---|---|
| 1 | I built the web layer as a **FastAPI** backend with an **HTML + Tailwind CSS** front end, plus a **command-line** version, in place of Flask or a static-only site. | FastAPI lets the interface trigger dataset generation and matching live, as Chapter 1 promises, while the command line keeps every result reproducible without a browser. I need to update Chapter 1 (objectives and §1.4) from Flask to FastAPI. |
| 2 | I moved the generator into `fello/dataset_generation/` and kept a flat layout rather than restructuring into a `src/` package. The matching code lives in `fello/matching/` and the tests in `fello/tests/`. `paths.py` puts `dataset_generation/` on the import path, so the generator's bare-name imports (`from schema import ...`) still work. | This keeps `schema.py`, `data_generation.py` and `visualize.py` byte-identical to the versions my supervisor reviewed. The only change to `generate_dataset.py` is its default output folder (see #15). |
| 3 | I use a **working dataset size of n = 3,000** for development, and will choose between 3,000 and 5,000 for the final evaluation based on replicate runtime. | At n = 3,000 the largest pool has about 730 profiles, which keeps the pairwise computations tractable. I keep the 50,000-profile dataset for data validation only. Running all five methods takes 26 s at n = 3,000 and 70 s at n = 5,000. |
| 4 | I set the **number of groups** in a pool to round(n/7), rounding half-up rather than using Python's banker's rounding, clamped to the feasible range [ceil(n/8), floor(n/6)]. Where no feasible count exists (n = 9, 10, 11, 17), I form as many groups of 8 as possible and log the rest as `remainder_not_absorbable`. | This targets groups of seven while guaranteeing every group has 6 to 8 members. The clamp never changes the result when round(n/7) is already feasible; it only makes the infeasible cases explicit instead of forcing an invalid group. |
| 5 | In **greedy construction**, a profile joins the open group where its marginal contribution is highest: (sum of homogeneity weights) × (1 − mean Gower distance to the current members), plus the weighted change in complementarity entropy. | A plain change in Score(G) is undefined for a one-member group, because a single member has no pairs and so no mean similarity. The marginal-contribution form keeps the homogeneity and entropy terms on the same scale at every group size. |
| 6 | I **seed the greedy step** from a seeded permutation of the pool: the first k profiles seed the k groups, and the rest are processed in permutation order. The seeding positions are written to each pool's log. | The seeding order has no theoretical preference, so I made it reproducible and logged instead. |
| 7 | In each **local-swap pass**, I evaluate every cross-group pair at once (vectorised, and verified against brute-force recomputation in `tests/test_group_assembly.py`), then apply the best improving swaps, at most one per group, highest gain first. | Allowing at most one swap per group keeps every applied gain exact, because the swaps touch disjoint groups, and evaluating all pairs per pass keeps the runtime practical. The total score strictly increases, so the procedure always terminates. At n = 3,000 and 5,000, every pool converged within 34 passes (limit 200). |
| 8 | I **swap only between grouped members**; profiles left over by the size plan are never swapped in. | This keeps the refinement step to rearranging existing groups. Who is left over is decided by the greedy order, and leftovers only occur in pools of 9, 10, 11 or 17. |
| 9 | For the **single-attribute baseline**, I break ties with a seeded shuffle followed by a stable sort on the attribute. | Without the shuffle, ties would keep the dataset's own order, which the generator produces in a fixed sequence. A random tie order is the neutral choice. |
| 10 | In the **random and single-attribute baselines**, the leftovers are the last profiles in shuffled or sorted order. | Every method uses the same group-size plan, so the unmatched count is identical across methods and never confounds the comparison. |
| 11 | I compute **Score(G) and the group details for the random and single-attribute groupings** under the default weighted objective. The unweighted-Gower baseline reports its own equal-weight score internally, and the evaluation will re-score every method under one common lens. | A cohesion index is only comparable across methods if it is computed the same way for all of them. |
| 12 | I word the **balance** of a group from its normalised entropy: ≥ 0.75 "well balanced", ≥ 0.40 "partly mixed", otherwise "dominated by one … (all/mostly X)". | This is a judgement call, as there are no established cut-offs. |
| 13 | When attributes **tie on mean similarity** in an explanation, I name the higher-weighted attribute first. | This keeps explanations deterministic and names the attribute the method values most. |
| 14 | I **implemented and log the adult-eligibility rule** even though it never excludes anyone. | Every generated profile is an adult, but I want every rule to be inspectable, not just the ones that exclude someone. |
| 15 | **All results go to `fello/output/`**: datasets to `output/n<n>/` and matching results to `output/matching/`. The locations are defined once in `paths.py`. `generate_dataset.py` resolves its default output folder from its own file location, and `run_matching.py` reads `output/n<n>/profiles_seed<seed>.csv`, saying which command generates it if the file is missing. | I want one shared output folder that every component reads from. The per-size subfolders stop datasets of different sizes overwriting each other, because the generator's file names carry the seed but not n. I moved the canonical 50,000-profile dataset to `output/n50000/` unchanged. |
